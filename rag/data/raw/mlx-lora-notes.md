# Fine-tuning with mlx_lm.lora and QLoRA

Local fine-tuning on this machine goes through MLX. The command is mlx_lm.lora. It trains a low-rank adapter on top of a frozen language model. LoRA leaves the base matrix where it is and learns a pair of small matrices whose product is the update. You store the adapter, not a second full copy of the network. Rank is the width of that update. A later comparison in this project changes rank and leaves the data, the seed, and the step count alone, so a loss gap can be attributed to rank.

QLoRA is that same adapter story with a quantized base. The base weights stay in low bit width, here a 4-bit checkpoint, and the adapter matrices stay in higher precision so the optimizer has a stable update. mlx_lm.lora takes the QLoRA path when the checkpoint you pass is already quantized. Point the same command at a full-precision model and the run is ordinary LoRA. This project does not quantize inside the training loop. It downloads an already quantized instruct model, which is why the run is QLoRA without a separate conversion step. The checkpoint we train is a 4-bit Llama 3.2 instruct model around one billion parameters. If a license gate blocks that download, the swap is a 4-bit Qwen 2.5 instruct model at about half a billion parameters, and the hyperparameters stay put. The swap, if it happens, is written down. The token used to accept a license stays outside the repo.

The data argument is a directory, not a single file. For a training run the loader requires train.jsonl. If valid.jsonl is in that directory, mlx_lm.lora reports validation loss during the run. test.jsonl is the file evaluate mode reads when the test flag is set. We keep all three. train.jsonl supplies the updates. valid.jsonl puts a validation loss in the log. test.jsonl stays held out for perplexity after training. Each line is one JSON object, and a single example must not be split across lines. The chat shape is a messages list: a user turn, then an assistant turn, each with a role and content. A prompt-plus-completion line and a raw text line are also legal shapes. This set uses chat so the model's own chat template can wrap the turns. Keys the loader does not expect are ignored, so labels hidden in extra fields will not enter the loss.

A few flags dominate when memory is tight. The documented default batch size is 4. This project uses one sequence at a time. The number of layers that receive adapters can be reduced, which shrinks the backward pass, and that cut is the documented response to an out-of-memory error. Sequence length is capped so one long note cannot blow the activation memory. Prompt masking, when it is on, drops the user tokens out of the loss and trains on the assistant span. For chat data the final message is the completion. The iteration count is a fixed budget, not an epoch count, so a small hand-written set still finishes in one sitting. Two hundred steps will not support a claim about which rank is universally better. They will show whether the loss moved, and whether rank 16 moved it differently from rank 8.

The adapter directory is the artifact. Learned weights land on disk and stay out of git. A resume points at the saved adapter file. Fusing the adapter back into the base is a separate command and is not part of the training log. What the log must contain is the iteration losses, so a parser can read the first train loss, the last train loss, and the last validation loss when valid.jsonl was present. The same data directory, the same seed, and the same flags are reused when the second run changes rank. If the command line and the YAML disagree, the command line wins, which is a reason to write the exact invocation next to the log.

Training stays on the host. A container on this plan does not expose Metal, so mlx_lm.lora is not something we expect to run inside that image. The quantized base plus the higher-precision adapter is the QLoRA setup the MLX guide describes, and the three files train.jsonl, valid.jsonl, and test.jsonl are the whole supervised set.
